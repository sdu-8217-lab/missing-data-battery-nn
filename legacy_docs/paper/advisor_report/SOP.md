# 技术报告制作 SOP（AI Agent 可复用）

本 SOP 总结自项目 EST-D-26-05697 的多次迭代经验，适用于"实验结果→可演示报告"的全流程。

---

## 一、核心原则

### 1. 先想清楚，再动手

**绝不跳过"想"直接做。** 在写任何内容之前，先完成以下思考：

- **目的**：报告要达成什么？（告知 / 说服 / 讨论）
- **受众**：谁看？看多久？技术水平？
- **信息量**：哪些信息对这次报告真正必要？
- **篇幅**：几页/几分钟？

想清楚后，把结论记录下来，再开始组织内容。

### 2. 先聚类，再设计

把想讲的散点内容按逻辑聚成若干主题块，每个块 = 一页/一屏。然后再做排版设计。

### 3. 每页一件事

**每一页只讲一个独立主题。** 读者可以不看上下文就能理解当前页。页与页之间可以跳读、可以只讲某一页。

### 4. 先填满，后删减

第一次填充时把必要信息都放进去（宁多勿少），然后逐条检查：这一段/这一句对当前页有没有贡献？没有就删。

### 5. 先大块，再细节

先设计页面的大布局（左右分栏？上图下表？全文字？），确定大块位置后再填充小元素（注释、箭头、颜色标注）。

### 6. 按节奏，分批做

- 批次一：图/表/数据（核心证据）
- 批次二：文字说明（围绕图表）
- 批次三：样式打磨（字体、间距、颜色）
- 批次四：自检与修正

---

## 二、制作流程

```
想 → 拆分 → 聚类 → 设计 → 填充 → 样式 → 校对 → 输出
```

### Step 1: 想（5-10 分钟思考，不写一行代码）

回答以下问题：
1. 报告的**目的**是什么？（告知 / 汇报 / 说服 / 讨论）
2. **受众**是谁？看多久？技术水平？
3. **信息边界**：哪些内容必须有？哪些可以不要？
4. **篇幅**：几页？每页信息密度？
5. **形式**：横版/竖版？有动画？

把答案写下来。这是后续所有决策的基础。

### Step 2: 拆分与聚类

1. 把要讲的内容全部列出（散点思维导图）
2. 按逻辑聚成主题块（每块 = 一页）
3. 确定块之间的顺序（时间线？重要性？论证链条？）
4. 每块写一句话标题，确认"这一页只讲这件事"

### Step 3: 设计页面布局

先设计几个典型的页面模板（不超过 3 种），然后所有页复用：

| 模板 | 适用场景 | 布局 |
|------|---------|------|
| 全图型 | 单张大图说清楚 | 图占 80%+ 面积，底部一行说明 |
| 图表并列 | 图+数据互相印证 | 左图右表 或 上图下表 |
| 纯数据表 | 多维度数据对比 | 占满版面的表格，脚注解释关键发现 |
| 文字页 | 结论/背景/过渡 | 少量文字，大字号，每行一个要点 |

### Step 4: 填充内容

**数据优先**：先画图、先造表，再写文字围绕它们。

**图**：
- 只画对本页有用的图，不要"为了好看"加装饰性图
- 横向布局用宽图（`figwidth=11-13`），纵向用标准图
- 配色不超过 4 种，区分度要高
- 标签用英文（兼容性），图注用中文（可读性）
- 保留 `.py` 源码，下次可直接修改

**表**：
- 每行每列都有意义，不留空白列/装饰性列
- 关键数字加粗或变色
- 每个表都加脚注说明"这张表在说什么"

**文字**：
- 每页文字控制在 80-120 字以内
- 用项目符号（itemize），不用长段落
- 一个要点 = 一句话

### Step 5: 样式打磨

- **字号**：正文 12-13pt，标题 14-16pt，注释 9-10pt
- **颜色**：只用 3-4 种主色，灰色用于次要信息
- **对齐**：表格数字右对齐，文字左对齐
- **间距**：`\vspace{}` 微调，让每页不要太空也不要太挤
- **页眉页脚**：每页都有统一样式（标题 + 副标题 + 分割线），底部有报告名和日期

### Step 6: 自检清单

每页完成后，逐项检查：

- [ ] 这一页只讲一个主题吗？
- [ ] 30 秒内能看懂吗？
- [ ] 有没有冗余内容？
- [ ] 图和表的数据一致吗？
- [ ] 注释够不够？（读者不需要查其他页就能理解）
- [ ] 前后页有没有重复内容？
- [ ] 图/表/文字有没有自相矛盾？
- [ ] 所有数字来源可追溯（CSV/实验结果）？

### Step 7: 编译与检查

```bash
# 编译两次（解决交叉引用）
xelatex -interaction=nonstopmode report.tex && xelatex -interaction=nonstopmode report.tex

# 检查输出
ls -lh report.pdf
```

- 如果有 Warning：大多是 `rerunfilecheck`，编译两次即可消除
- 如果有 Error：优先查 `\\`（段落末尾换行）和 `\hrule`（无高度行）的问题
- 用 `grep "Output written\|Error\|Overfull" report.log` 快速定位

## 三、风格规则

### 3.1 语言

- **正文/图注/表格脚注**：中文
- **变量/方法名/数据列名**：英文原样保留（如 MAE、GraphMIM、bernoulli）
- **中英文之间**：加空格（如"GraphMIM 在 NASA 数据集"）
- **避免**：长段落、被动句式、"我们"（改用"本报告"或省略主语）

### 3.2 数字

- **4 位小数**：0.0241（MAE/RMSE 等精度指标）
- **1 位小数**：12.8%（百分比改进/差距）
- **千位分隔**：35,100（大数字）
- **来源**：所有数字必须从 CSV/experiment_results 追溯，不可手写

### 3.3 可视化

| 元素 | 推荐值 |
|------|--------|
| 图宽（横向A4） | 11-13 inch |
| 图宽（纵向A4） | 7-9 inch |
| dpi | 180-200（PDF内嵌） |
| 配色方案 | 暖色=重点方法，冷色=对比方法，灰色=基线/参考 |
| 字号 | 图内标签 12-14pt，注释 10-11pt |

### 3.4 排版

| 项目 | 值 |
|------|-----|
| 纸张 | 横向 A4：`landscape, a4paper` |
| 页边距 | 上下 1.5cm，左右 1.6cm |
| 正文字号 | 11pt（ctexart） |
| 行距 | 默认（`\renewcommand{\arraystretch}{1.2}` 表格内） |

## 四、错误模式与规避

| 错误 | 后果 | 规避方法 |
|------|------|---------|
| 不想直接做 | 逻辑断裂、内容散乱 | 强制 Step 1 写下 5 个问题的答案 |
| 每页讲太多 | 读不完、抓不住重点 | 每页字数上限 120 字 |
| 图和表重复 | 浪费版面、信息冗余 | 图和表各讲一个维度，不重复同一组数字 |
| 数据手写 | 数字错误、无法追溯 | 永远从 CSV 读数，不用手动填 |
| 图做好不更新文字 | 图说 A、文字说 B | 改图 = 同步改表 = 同步改文字 |
| 把"建议"写成"事实" | 被质疑说服性 | 用"可以/能够"替代"应该/建议" |
| 页间重复 | 内容膨胀、读者疲劳 | 检查前后页，重复内容删除或合并 |
| 一个方法讲多页 | 篇幅失控 | 一个方法 = 一页，跨方法对比另起一页 |

## 五、交付标准

- [ ] 所有图/表/文字编译无 Error
- [ ] 每页独立可读，不依赖上下文
- [ ] 所有数字可追溯到 CSV/experiment_results
- [ ] 自检清单全部通过
- [ ] PDF 大小合理（< 1MB）
- [ ] 图片源码（.py）保留，与 PDF 图一致
