## 1. 置信度定义

置信度不是"质量评级"，而是**知识溯源链的完整度标识**。

### 1.1 四级置信度

| 等级 | 标识 | 颜色 | 人类审查 | AI参与 | 知识溯源链 |
|------|------|------|---------|--------|-----------|
| **S** | 🟢 | 绿色 | 100%人工编写 | 0% | 人类观察→人类推理→人类表达 |
| **A** | 🟡 | 黄色 | 人工审核+AI辅助 | AI生成，人工验证推理过程 | 人类观察→AI辅助→人类验证→人类表达 |
| **B** | 🟠 | 橙色 | 人工快速浏览 | AI生成，人工关键处修改 | 人类观察→AI生成→人类修正→表达 |
| **C** | 🔵 | 蓝色 | 无人审查 | 100%自动生成 | 代码/数据→自动生成→无审查 |

### 1.2 置信度语义详解

#### 🟢 S级（权威）

**定义**：经项目负责人完全审查的核心原则文档

**特征**：
- 反映项目核心设计决策
- 经过充分讨论和验证
- 变更频率极低（月/年级）
- 错误可能导致系统性风险

**示例**：
- 9层实验架构定义
- 核心科研假设
- 安全策略

**修改权限**：项目负责人
**审查要求**：任何修改需RFC流程

#### 🟡 A级（审查）

**定义**：经核心成员完整审查的操作文档

**特征**：
- 准确反映当前系统状态
- 定期审查（建议3个月周期）
- 变更需人工验证
- 错误可能导致操作失误

**示例**：
- 用户指南
- API文档
- 安装说明

**修改权限**：核心成员
**审查要求**：修改后需另一人审查

#### 🟠 B级（协作）

**定义**：AI生成为主、人工修正的辅助文档

**特征**：
- 内容可能部分过时
- 变更较频繁（周级）
- 关键信息已人工确认
- 错误影响有限

**示例**：
- 教程
- 故障排查
- 配置示例

**修改权限**：所有贡献者
**审查要求**：关键处人工确认

#### 🔵 C级（自动）

**定义**：完全自动生成、无人审查的参考文档

**特征**：
- 从代码/配置自动生成
- 实时同步
- 仅供参考
- 可能存在偏差

**示例**：
- CLI命令参考
- API函数列表
- 配置项说明

**修改权限**：自动化流程
**审查要求**：无（依赖生成源准确性）

## 2. 标记规范（强制）

### 2.1 标记格式

每个文档头部必须包含**HTML注释形式的元数据**：

```html
<!-- 
  confidence: [S|A|B|C]
  reviewed: YYYY-MM-DD
  reviewer: [姓名或用户名]
  ai-assisted: [true|false]
  commit: [git-short-hash]
  expires: [YYYY-MM-DD|never]
-->
```

### 2.2 字段说明

| 字段 | 必填 | 说明 | 示例 |
|------|------|------|------|
| `confidence` | ✅ | 置信度等级 | `confidence: A` |
| `reviewed` | ✅ | 最后审查日期 | `reviewed: 2026-03-19` |
| `reviewer` | ✅ | 审查人标识 | `reviewer: chen` |
| `ai-assisted` | ✅ | 是否AI辅助生成 | `ai-assisted: true` |
| `commit` | 建议 | 对应代码版本 | `commit: c87f6b7` |
| `expires` | 可选 | 过期日期 | `expires: 2026-06-19` |

### 2.3 标记示例

#### S级示例
```markdown
<!-- 
  confidence: S
  reviewed: 2026-03-19
  reviewer: chen
  ai-assisted: false
  commit: c87f6b7
  expires: never
-->

# 项目核心架构
...
```

#### A级示例
```markdown
<!-- 
  confidence: A
  reviewed: 2026-03-19
  reviewer: chen
  ai-assisted: true
  commit: c87f6b7
  expires: 2026-06-19
-->

# 用户指南
...
```

#### B级示例
```markdown
<!-- 
  confidence: B
  reviewed: 2026-03-19
  reviewer: chen
  ai-assisted: true
-->

# 快速教程
⚠️  本教程基于AI生成，关键步骤已人工验证，但细节可能过时。
...
```

#### C级示例
```markdown
<!-- 
  confidence: C
  reviewed: auto
  reviewer: github-actions
  ai-assisted: true
-->

<!-- 
  警告：本文档由工具自动生成，未经人工审查。
  生成时间：2026-03-19 00:00:00
  生成工具: mkdocstrings
-->

# API参考
...
```

## 3. 置信度管理流程

### 3.1 升级流程

```
B → A：
  1. 人工完整阅读全文
  2. 验证所有技术细节与代码一致
  3. 修正过时内容
  4. 更新审查日期和审查人
  5. 提交PR，请求A级审查

A → S：
  1. 项目负责人完整审查
  2. 确认内容反映核心设计原则
  3. 锁定编辑权限（CODEOWNERS）
  4. 发布版本标签
  5. 更新审查日期，设置expires: never
```

### 3.2 降级与过期

**自动降级规则**：
- A级文档超过**6个月**未审查 → 自动降级为B级
- B级文档超过**3个月**未审查 → 添加"⚠️ 可能过时"警告

**过期处理**：
```markdown
<!-- expires: 2026-06-19 -->
```

过期后文档：
- 保留可读性
- 添加醒目过期警告
- 链接到最新版本

### 3.3 变更追踪

所有置信度变更应记录：

```markdown
## 变更历史

| 日期 | 操作 | 从 | 到 | 审查人 | 说明 |
|------|------|----|----|--------|------|
| 2026-03-19 | 创建 | - | S | chen | 初始版本 |
| 2026-06-20 | 降级 | S | A | chen | 架构微调，待验证 |
```

## 6. 常见问题

### Q1: 为什么用HTML注释而非YAML Front Matter？

**YAML Front Matter**：
```markdown
---
confidence: A
reviewed: 2026-03-19
---
```

**对比**：

| 特性 | HTML注释 | YAML Front Matter |
|------|---------|-------------------|
| Markdown原生支持 | ✅ | ⚠️ 需解析器 |
| 渲染可见性 | 隐藏 | 部分渲染器显示 |
| 工具复杂度 | 低 | 需YAML解析器 |
| 扩展性 | 足够 | 过度设计 |

**结论**：本项目采用简洁主义，HTML注释足够。

### Q2: AI辅助生成的S级文档可能吗？

**原则**：S级要求"100%人工编写"，AI**参与即非S级**。

**边界情况**：
- 使用AI检查语法 → 仍属S级（AI仅辅助表达，不参与内容）
- 使用AI生成初稿 → 降至A级（AI参与了内容创作）

### Q3: 如何批量更新文档置信度？

```bash
# 示例：批量添加置信度标记
for file in docs/*.md; do
  # 检查是否已有标记
  if ! grep -q "<!-- confidence:" "$file"; then
    # 添加B级默认标记
    sed -i '1i\
<!-- \
  confidence: B\
  reviewed: 2026-03-19\
  reviewer: chen\
  ai-assisted: true\
-->
' "$file"
  fi
done
```
